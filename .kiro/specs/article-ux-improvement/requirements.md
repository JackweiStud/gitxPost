# X Article 工作站用户体验优化需求

## 问题分析

当前文章工作流存在以下体验问题：

### 1. 工作流割裂
- 用户需要手动触发每个步骤（生成骨架 → 生成全文 → 发布）
- 每个步骤之间需要等待，无法连续操作
- 步骤切换不流畅，缺少自动化

### 2. 反馈不够直观
- WebSocket 更新后只有小的状态消息
- 生成过程中看不到具体进度
- 错误信息不够明显

### 3. 编辑体验不佳
- 标题和内容编辑分离
- 左右分栏占用空间大，预览不够清晰
- 缺少快捷操作

### 4. 界面信息密度低
- 步骤指示器占用空间大但信息量少
- 按钮分散，操作不集中
- 缺少上下文信息

## 优化目标

### 核心目标
1. **简化工作流**：一键生成，自动完成骨架 → 全文流程
2. **增强反馈**：实时进度、清晰状态、明显错误提示
3. **优化布局**：更紧凑的界面，更大的编辑空间
4. **提升效率**：快捷键、自动保存、智能建议

## 功能需求

### FR-1: 一键生成工作流

**FR-1.1 智能生成模式**
- 用户输入标题后，选择文章风格（zara/tech/fun）
- 点击"一键生成"按钮
- 系统自动完成：生成骨架 → 等待 → 生成全文
- 每个步骤完成后自动进入下一步
- 用户可以随时中断流程

**FR-1.1.1 风格选择器**
- 提供下拉选择器或单选按钮组
- 支持三种风格：
  - zara：Zara 风格（默认）
  - tech：技术风格
  - fun：趣味风格
- 显示每种风格的简短描述
- 记住用户上次选择的风格

**FR-1.2 手动模式保留**
- 保留"仅生成骨架"选项
- 用户可以在骨架阶段编辑后再生成全文
- 提供"重新生成"选项

**FR-1.3 进度可视化**
- 显示当前步骤和预计时间
- 显示实时进度条
- 显示步骤状态（等待/进行中/完成/失败）

### FR-2: 优化编辑界面

**FR-2.1 紧凑的顶部栏**
- 标题、状态、操作按钮集中在一行
- 步骤指示器改为小型徽章
- 减少垂直空间占用

**FR-2.2 可切换的预览模式**
- 默认：编辑器全屏（左侧）+ 小预览（右侧可折叠）
- 预览模式：预览全屏 + 编辑器隐藏
- 分屏模式：50/50 分屏（当前模式）

**FR-2.3 浮动操作面板**
- 主要操作按钮固定在右下角
- 包含：保存、生成、发布、预览切换
- 显示保存状态（已保存/未保存/保存中）

### FR-3: 增强状态反馈

**FR-3.1 进度指示器**
- 生成骨架：显示"正在分析主题..."（0-30%）→ "正在生成大纲..."（30-70%）→ "正在优化结构..."（70-100%）
- 生成全文：显示"正在扩展章节 1/5..."等具体进度
- 发布：显示"正在上传..."→ "正在发布..."

**FR-3.2 状态通知**
- 成功：绿色通知 + 动画效果
- 错误：红色通知 + 详细错误信息 + 重试按钮
- 警告：黄色通知 + 建议操作

**FR-3.3 实时内容更新**
- 生成过程中实时显示生成的内容（流式输出）
- 内容更新时有平滑的动画效果
- 自动滚动到最新内容

### FR-4: 快捷操作

**FR-4.1 键盘快捷键**
- Cmd/Ctrl + S：保存
- Cmd/Ctrl + P：预览切换
- Cmd/Ctrl + Enter：生成/发布（根据当前步骤）
- Cmd/Ctrl + Z：撤销
- Cmd/Ctrl + Shift + Z：重做

**FR-4.1.1 图片插入功能**
- 支持拖拽图片到编辑器
- 支持点击工具栏按钮选择图片
- 支持粘贴剪贴板图片（Cmd/Ctrl + V）
- 自动上传图片并插入 Markdown 语法
- 显示上传进度和预览

**FR-4.2 自动保存**
- 内容变化后 3 秒自动保存
- 显示"自动保存于 XX:XX"
- 保存失败时提示并重试

**FR-4.3 智能建议**
- 标题过长/过短时提示
- 内容字数统计和建议
- 发布前检查清单（标题、内容长度、格式等）

### FR-5: 列表页优化

**FR-5.1 快速操作**
- 卡片上直接显示"继续生成"按钮（如果未完成）
- 显示生成进度（如果正在生成）
- 一键复制文章链接（如果已发布）

**FR-5.2 筛选和排序**
- 按状态筛选：全部/草稿/已发布
- 按步骤筛选：标题/骨架/内容/已发布
- 排序：最新更新/创建时间/标题

**FR-5.3 批量操作**
- 批量删除草稿
- 批量导出为 Markdown
- 批量标记为归档

## 非功能需求

### NFR-1: 性能
- 页面加载时间 < 1 秒
- 自动保存响应时间 < 500ms
- WebSocket 消息延迟 < 100ms

### NFR-2: 可用性
- 所有操作提供明确反馈
- 错误信息清晰且可操作
- 支持移动端响应式布局

### NFR-3: 可靠性
- 自动保存防止数据丢失
- WebSocket 断线自动重连
- 操作失败自动重试（最多 3 次）
