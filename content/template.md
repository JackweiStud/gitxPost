# X Article 格式规范 (最低要求)

所有生成的文章必须满足以下格式，以确保 `xpost publish` 和 `parse_markdown.py` 能正常工作。

---

## 硬性约束 (必须遵守)

### 1. 标题
- 必须以 `# 标题` 开头 (H1 级别)
- 会被提取为 X Article 的标题

### 2. 封面图
- **第一张图片** 会自动作为封面图
- 格式: `![描述文字](images/cover.png)`
- 路径支持相对路径 `images/xxx.png`

### 3. 内容图片
- 后续图片会被解析并插入 X Article 编辑器
- 格式: `![描述](images/demo1.png)`
- 建议放在段落之后，作为独立行

### 4. Markdown 语法
支持以下标准语法：

| 元素 | 语法 | 说明 |
|---|---|---|
| 二级标题 | `## 标题` | 用于章节划分 |
| 三级标题 | `### 标题` | 用于小节划分 |
| 引用块 | `> 内容` | 用于金句、重点强调 |
| 无序列表 | `- 项目` | 用于列举 |
| 有序列表 | `1. 项目` | 用于步骤 |
| 粗体 | `**文字**` | 强调 |
| 斜体 | `*文字*` | 次级强调 |
| 链接 | `[文字](URL)` | 外链 |
| 代码块 | ` ``` code ``` ` | 代码展示 |

### 5. 分隔线 (可选)
- `---` 会被转换为 X Articles 的 Divider
- 常用于文章结尾和签名之间

---

## 软性建议 (可自由调整)

以下内容 **不是** 硬性约束，可根据风格自由安排：

- 章节数量和标题名称
- 内容结构和顺序
- 开场 Hook 的具体写法
- 结语和 Call to Action
- @用户签名
- HTML 注释 `<!-- ... -->` (会被自动过滤)

## 验证方法

生成文章后，运行以下命令验证格式：

```bash
python article_tooling/scripts/parse_markdown.py <your_article.md> --output json
```

预期输出应包含：
- `title`: 非空字符串
- `cover_image`: 有效图片路径
- `content_images`: 数组 (内容图片列表)
- `html`: 非空 HTML 内容
